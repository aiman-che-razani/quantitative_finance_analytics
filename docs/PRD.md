## 1. Problem & user

Axiom is a local, single-user research workspace for one solo quant/engineer (Aiman) who wants reproducible daily-bar research, backtesting and paper-tracking on his own machine, plus a legible, honestly-labeled artifact he can show on his portfolio site without exposing a live backend or a private API token. It is not a multiuser product, not a broker, and not a hosted service (README "What each phase delivers" and the sentence after it, README "Docker", `docs/roadmap.md` closing paragraph).

## 2. Goals / non-goals

**Goals**
- Deterministic, auditable daily-bar research: ingest → validate → snapshot → feature → backtest/ML → risk-checked orders → ledger → analytics → durable experiment record (README "Architecture" diagram).
- Two coexisting generations: the filesystem-only V0.1 CLI (`axiom/cli.py` → `axiom/research.py`, documented in `docs/v0.1-guide.md`) stays available alongside the PostgreSQL-backed V0.2+ platform; any new proposal must say which generation it targets (README intro; `docs/decisions/0001-keep-v0.1-and-v0.2-coexisting.md`).
- A portfolio-safe public showcase: `docs/showcase.json`, produced by `scripts/export_showcase.py`, lets the `personalportfolio` `dev` route show precomputed, provenance-stamped, explicitly synthetic-vs-observed results without a private API token, while the interactive workspace stays on `127.0.0.1:8821` (README "Portfolio"). Verified 2026-09-29: `docs/showcase.json` holds six records (three `provider: "yahoo"` SPY, three `provider: "synthetic-v2"`), each with `provenance.dataset_id`, `code_commit` `4f4d702`, `code_tree_sha256`, and `working_tree_dirty: false`. The re-export in `0e88254` left the three Yahoo records' `metrics`, `series` and `monthly_returns` byte-identical to the previous export (checked by diffing against `4f4d702:docs/showcase.json`); the synthetic records were rebuilt from the Windows-built dataset `8ce51d9e…` and differ only in last-digit floating point.

**Non-goals (V1.0, from README "What each phase delivers", "Data and paper execution", "Docker", "Limitations and next improvements")**
- Exchange connectivity, real-money execution, tick-level simulation, a publicly authenticated multiuser service.
- Point-in-time universe membership, total-return adjustment, borrow/financing/margin/taxes, real order routing.
- Daily US ETF price data only — no tick/quote feed.
- Public deployment without a real auth layer, TLS, quotas, backups (Docker Compose binds app ports only to `127.0.0.1`: `compose.yaml` `127.0.0.1:8820:8820` and `127.0.0.1:8821:8821`).

New non-goals should be appended here with a reason, never silently removed.

## 5. Requirements as user stories

1. **As a researcher, I can re-ingest an overlapping date range and get the same dataset id if the data is unchanged, or an explicit rejection if it conflicts or leaves a gap.**
   Acceptance: `tests/test_platform.py::test_incremental_overlap_and_paper_idempotency`, `::test_incremental_conflicting_overlap_is_rejected_and_head_unchanged`, `::test_incremental_ingest_rejects_a_gap_and_keeps_the_head`; `tests/test_validation.py::test_exact_duplicate_and_conflict`. Implementation: `axiom/data/incremental.py`.

2. **As a researcher, a crash or torn write during snapshot publish never leaves a permanently corrupt dataset.**
   Acceptance: `tests/test_validation.py::test_snapshot_write_cleans_staging_and_tolerates_concurrent_publish`, `::test_rewriting_a_corrupted_snapshot_repairs_it`, `::test_fsync_opens_files_writable_only_on_windows`, `::test_snapshot_write_rejects_an_empty_frame`. Implementation: `axiom/data/storage.py`. Cleanup of orphaned snapshot directories is `scripts/prune_snapshots.py` (untested, dry run by default, guarded).

3. **As a researcher, I can run a backtest with any of market/limit/stop/stop-limit orders, including shorts and partial fills, and trust that the ledger reconciles.**
   Acceptance: `tests/test_execution.py` (stop/limit/stop-limit, sell orders, short leverage, reversal reconciliation), `tests/test_backtest.py` (next-open execution, fractional-cash costs), `tests/test_platform.py::test_partial_fills_are_next_bar_and_reconcile`. Implementation: `axiom/backtest/events.py`, `axiom/portfolio/account.py`.

4. **As a researcher, every order is subject to pre-trade risk checks (leverage, concentration, drawdown, daily/portfolio loss, position sizing) with no bypass path.**
   Acceptance: `tests/test_execution.py::test_short_leverage_reserves_commissions`, `::test_risk_clips_and_allows_exit_during_loss_halt`, `::test_loss_circuit_breakers_reject_in_isolation`, `::test_loss_circuit_breakers_allow_within_limits`, `::test_risk_rejects_disabled_short_and_nonpositive_equity`; `tests/test_platform.py::test_stop_loss_and_take_profit_exit_at_trigger_price` (risk-per-trade sizing). Implementation: `axiom/risk/engine.py`; the only `assess(` call site is in `axiom/backtest/events.py`, and `axiom/paper.py` replays exclusively through `run_events`, so no paper order path bypasses the risk engine. Risk-reducing closes are always approved by design.

5. **As a researcher, I can run walk-forward ML with purged splits and see out-of-sample trading metrics reported separately from classification metrics, with a null reference for any AUC I quote.**
   Acceptance: `tests/test_platform.py::test_horizon_purges_and_nonoverlapping_test_windows`, `::test_walk_forward_reports_all_four_models`, `::test_null_auc_summarises_every_model_deterministically`. Implementation: `axiom/ml/walkforward.py`. Evidence of a full run: `docs/ml-validation.json` (synthetic only). The dashboard shows pooled AUC without a null and says so on the page; only `scripts/demo_ml.py`-style runs with `null_auc()` produce a comparable null.

6. **As a researcher, I can call the API only with a bearer token, the browser never sees that token, and errors map to predictable status codes.**
   Acceptance: `tests/test_platform.py::test_api_requires_authentication`, `::test_api_rejects_duplicate_symbols_and_unknown_accounts`, `::test_api_experiment_and_paper_round_trip`, `::test_api_list_and_market_endpoints_return_recorded_rows`; `apps/dashboard/app/api/[...path]/route.ts` holds `API_TOKEN` server-side only (manual/Chromium evidence). Implementation: `axiom/api.py`.

7. **As a researcher, every experiment records enough provenance (dataset hash, code commit, dirty flag, source-tree hash) to know exactly what produced a result.**
   Acceptance: `tests/test_platform.py::test_experiment_provenance_is_recorded` (V0.2+ platform); `tests/test_integration.py::test_ten_instrument_research_reproducible` (V0.1 CLI). Implementation: `axiom/platform.py` `run_experiment`; `axiom/research.py` (V0.1). Downstream: every `docs/showcase.json` record carries a clean-tree (`working_tree_dirty: false`) provenance block at `4f4d702`.

8. **As a researcher, I can advance a paper account's clock and get the same fills if I repeat the tick, a rejection if I move it backwards or the history/provider changed, and the account keeps the feature settings it was created with.**
   Acceptance: `tests/test_platform.py::test_incremental_overlap_and_paper_idempotency`, `::test_paper_rejects_changed_history_and_foreign_provider`, `::test_api_experiment_and_paper_round_trip` (409 on backwards; `features` persisted). Implementation: `axiom/paper.py` (row-locked `advance`).

   Acceptance: `tests/test_platform.py::test_paper_stale_input_alert`, `::test_paper_stale_alert_persists_on_repeat_ticks_without_new_bars`, `::test_paper_risk_rejection_alert`, `::test_record_tick_failure_merges_alerts`, `::test_successful_repeat_tick_clears_tick_failure`. ## 6. Honesty & scope requirements

- Synthetic and provider-sourced data are never silently interchanged. Mechanism: `provenance.provider` on every `docs/showcase.json` record (`yahoo` or `synthetic-v2`) and on `docs/ml-validation.json`; README "Data and paper execution": "Providers never silently substitute simulated data."
- No result in this repo is described as real trading. `axiom/paper.py` module docstring: "Idempotent paper replay; never sends orders to a broker."; README: "No real-money broker adapter exists."
- ML out-of-sample trading metrics and classification metrics are reported together, never substituted for each other (README phase table V0.5; `axiom/ml/walkforward.py`). Pooled AUC is compared with a random-walk null, not 0.5, wherever skill might be inferred; the dashboard, which does not compute the null, says its AUC values are not evidence of skill.
- The risk engine's pre-trade checks apply to every fill (§5 story 4).
- Performance/scale claims cite `docs/benchmarks/results.json` and are labeled development-machine observations, not service guarantees (README "Measured scaling"; `results.json` `method`). The 56.66 s → 17.05 s (3.3×) replay figure must always carry the caveat that it is not an isolated measure of the optimization.
- Uncommitted observations are labeled as such: the "nine cumulative fills" live paper tick has no committed artifact; `docs/verification-evidence.json` was generated from a pre-commit working tree.
- The fixed Yahoo universes (10 hand-picked ETFs in `docs/verification-evidence.json`; SPY in `docs/showcase.json`; any 60-ETF study) carry selection and survivorship bias (README "Limitations"; `docs/architecture-v1.md`).
