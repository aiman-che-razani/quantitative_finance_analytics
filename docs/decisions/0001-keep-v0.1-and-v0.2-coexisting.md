# 0001: Keep the V0.1 CLI/engine and the V0.2+ platform as two coexisting code paths

## Status

Accepted (reflects the current, shipped state of the codebase as of this
writing; not a proposal).

## Context

Axiom contains two real, independently runnable generations of the same
research pipeline:

- **V0.1**: `axiom/cli.py` → `axiom/research.py` (`ingest`, `research`) →
  `axiom/backtest/engine.py` + `axiom/strategies/simple.py` +
  `axiom/analytics/metrics.py`. Filesystem-only: plain `data/`/`reports/`
  directories, no PostgreSQL, one independent account per symbol (not a
  multiasset portfolio; see `research.py:142`). Documented in
  `docs/v0.1-guide.md`.
- **V0.2+**: the PostgreSQL-backed platform — `axiom/data/incremental.py`,
  `axiom/metadata.py`, `axiom/backtest/events.py` (multi-asset event replay
  with risk checks), `axiom/platform.py`, `axiom/paper.py`, `axiom/api.py`,
  `apps/dashboard/`.

Both paths currently share only the lowest layers: `axiom/common/models.py`,
`axiom/data/providers.py`, `axiom/data/validation.py`, `axiom/data/storage.py`
(`SnapshotStore`), and `axiom/features/pipeline.py`. Above that they fully
diverge: two backtest engines (`backtest/engine.py` vs `backtest/events.py`),
two metrics modules (`analytics/metrics.py` vs `analytics/extended.py`), two
entry points (`cli.py` vs `api.py`), and two config shapes (`BacktestConfig`
vs `ExecutionConfig`/`RiskConfig`).

V0.1 is not vestigial: it is still exercised by
`tests/test_backtest.py`, `tests/test_analytics.py` and
`tests/test_integration.py`, it is still the documented "run now" quick start
in `docs/v0.1-guide.md`, and `README.md:3` still links to it directly
("The original V0.1 CLI remains available"). Nothing in the README or roadmap
states *why* it was kept rather than migrated onto the V0.2+ engine or
deleted — this ADR records that reasoning so a future cleanup pass does not
remove it as presumed dead code, and so a future contributor changing either
engine knows the other one exists and is real.

`roadmap.md:5` frames V0.1 as milestone zero of an iterative build ("V0.2
metadata/ingestion, V0.3 event execution/accounting/risk, ... V1.0"), i.e. the
platform was built as a sequence of additive milestones on top of V0.1 rather
than as a V0.1 rewrite.

## Decision

Keep V0.1 (`axiom/cli.py`, `axiom/research.py`, `axiom/backtest/engine.py`,
`axiom/strategies/simple.py`, `axiom/analytics/metrics.py`) running,
documented and tested alongside the V0.2+ platform, rather than:

- migrating V0.1's callers onto `backtest/events.py`/`ExecutionConfig` and
  deleting the older engine, or
- hiding/deprecating the V0.1 CLI now that the API and dashboard exist.

The two engines are allowed to diverge in behavior (V0.1: one account per
symbol, simple next-open fills, no risk engine; V0.2+: shared multi-asset
portfolio, `risk.engine.assess()` on every fill, PostgreSQL-tracked
provenance) because they serve different jobs, not because one is a strict
subset of the other. Per this agent's invariant 13, any future change to
*this specific split* (merging the engines, retiring V0.1, or changing which
layers V0.1 depends on) requires its own ADR rather than a quiet refactor.

## Consequences

- **No database required for a quick, reproducible local backtest.** V0.1
  needs no PostgreSQL, no `.env`, no running API/dashboard — `axiom demo`
  works from a bare checkout with only `data/`/`reports/` directories
  (`docs/v0.1-guide.md:8-18`). This is a meaningfully lower floor than the
  V0.2+ platform, which requires `Settings.database_url`/`api_token`
  (`axiom/settings.py:9-10`) and a running Postgres instance.
- **Two engines to keep correct.** A fix to shared assumptions (e.g. execution
  timing, cost modeling) must be considered for both `backtest/engine.py` and
  `backtest/events.py` independently; they are not guaranteed to agree, and
  today they do not share code above `features/pipeline.py`.
- **Two metrics implementations** (`analytics/metrics.py` vs
  `analytics/extended.py`) can silently diverge in definition (e.g. Sharpe,
  drawdown) since neither is derived from the other; a reader comparing a
  V0.1 report to a V0.2+ experiment result is comparing two independently
  implemented metric sets, not the same code path evaluated twice.
- **Higher review surface.** Reviewers and this agent must check whether a
  proposed change belongs in one engine, the other, or the shared lower
  layers (`common/models.py`, `data/`, `features/pipeline.py`), and must
  avoid "fixing" V0.1 by silently pointing it at V0.2+ internals (or vice
  versa) without an ADR, since that would be exactly the kind of schema/split
  change invariant 13 flags.
- **Tests must keep covering both paths.** `tests/test_backtest.py` and
  `tests/test_integration.py` exercising V0.1 is load-bearing evidence that
  it still works; if that coverage is ever dropped, V0.1's "still exercised"
  status (and this decision's premise) should be re-examined.
