## 2. ML inside the app
Today Axiom's only model-based feature is the walk-forward classifier in `axiom/ml/walkforward.py`, run through `POST /experiments` with `kind="ml"` (`axiom/platform.py::run_experiment`). It is classical scikit-learn/XGBoost, fit fresh per request, with no persisted model artifact and no LLM anywhere in the codebase. When a model feature is proposed, enforce:
1. **Fit on train, select on validation, evaluate once on test.** `splits()` (`axiom/ml/walkforward.py:30`) yields expanding `(train, validation, test)` windows with a `horizon`-length purge gap before *and* after validation (`test_start = train + validation + 2*horizon`); every candidate (the three `LogisticRegression` strengths) is fit on `x[a:b]` only and picked by validation `log_loss` on `x[c:d]`; final metrics come from `x[e:f]`. A new candidate model must follow the same fit/select/evaluate separation — no fitting or model selection that touches the test slice.
2. **Single instrument only, on purpose.** `walk_forward` raises if `frame["instrument"].n_unique() != 1` (`walkforward.py:45`); the README says this "deliberately does not mix cross-sectional rows into chronological splits". Relaxing this is an `architecture` decision (cross-sectional leakage across symbols is a real risk), not a quiet code change.
3. **Two different metric families answer two different questions — report both, never substitute one for the other.** `fold["models"][name]` (accuracy/balanced_accuracy/log_loss/roc_auc) measures classification quality on held-out labels; `out_of_sample_trading[name]` (`analyze(result, benchmark)`) replays the same predictions through `run_events(..., "ml", ...)`, the identical engine used for rule strategies, benchmarked against `buy_hold` over the same window. A high classification score does not imply good trading metrics or vice versa.
4. **Fixed seeds everywhere.** `random_state=42` on `LogisticRegression`, `RandomForestClassifier` and `XGBClassifier`; `SyntheticProvider(seed=42)` is the default data seed. A new candidate must set an explicit seed or say why determinism doesn't apply.
5. **No model persistence today.** `walk_forward` fits and discards every estimator inside one call; nothing is pickled to disk. If a feature adds model persistence (save/reload across requests), that opens a new deserialization trust boundary that does not exist today — route it through `security` before it ships, and it likely needs an ADR from `architecture`.
6. **Synthetic data validates software, not skill.** The README's own limitations section says results on `SyntheticProvider`/`benchmark_universe` data "validate software behavior and cannot establish predictive value"; a claim of predictive skill needs Yahoo-sourced data (`YahooProvider`) and must say so plainly, including the fixed-universe Yahoo study's selection/survivorship bias.
7. **Causal features only.** `FEATURES` (`walkforward.py:19`) are drawn from `axiom/features/pipeline.py`'s output and gated on the `ready` flag; a new feature must be computable from information available at or before the bar's close and must not leak `forward_return`-adjacent information.
8. **LLM features** (none exist; none are planned): if proposed, they must never sit in the risk/execution decision path (`axiom/risk/engine.py`, `axiom/backtest/events.py`) unattended, must never treat unlabelled market data, tickers or free-text fields as instructions (prompt injection), and tests must not use the network; use the official Anthropic SDK and load the `claude-api` skill for current model IDs instead of recalling them.
