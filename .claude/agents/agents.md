## 2. ML inside the app
Today Axiom's only model-based feature is the walk-forward classifier in `axiom/ml/walkforward.py`, run through `POST /experiments` with `kind="ml"` (`axiom/platform.py:61-64`, which imports `walk_forward` lazily inside `run_experiment`). It is classical scikit-learn/XGBoost, fit fresh per request, with no persisted model artifact and no LLM anywhere in the codebase. When a model feature is proposed, enforce:
1. **Fit on train, select on validation, evaluate once on test.** `splits()` (`axiom/ml/walkforward.py:32-40`) yields expanding `(train, validation, test)` windows with a `horizon`-length purge gap before *and* after validation (`test_start = train + validation + 2*horizon`, line 35); every candidate (three `LogisticRegression` strengths, lines 77-89) is fit on `x[a:b]` only and picked by validation `log_loss` on `x[c:d]`; final metrics come from `x[e:f]` (lines 116-128). A new candidate must follow the same fit/select/evaluate separation — no fitting or model selection that touches the test slice.
2. **Single instrument only, on purpose.** `walk_forward` raises if `frame["instrument"].n_unique() != 1` (`walkforward.py:52-53`). Relaxing this is an `architecture` decision (cross-sectional leakage across symbols is a real risk), not a quiet code change.
3. **Two metric families answer two different questions — report both, never substitute one for the other.** `fold["models"][name]` (accuracy/balanced_accuracy/log_loss/roc_auc, `walkforward.py:121-128`) measures classification quality on held-out labels; `out_of_sample_trading[name]` (`walkforward.py:143-163`) replays the same predictions through `run_events(..., "ml", ...)`, the engine used for rule strategies, benchmarked against `buy_hold` over the same window. A high classification score does not imply good trading metrics or vice versa.
4. **AUC is evidence of skill only if it clears the null p95, not 0.5.** Per-fold AUC on a short window is biased above 0.5 even without signal (`walkforward.py:135-136`); `pooled_test_auc` (lines 137-140) shrinks that bias but does not remove it. `null_auc()` (`walkforward.py:188-212`) runs the same splits on `random_walk_surrogate` series (driftless, volatility-matched) and reports per-model `mean`/`p95`; its docstring (line 193) states the rule. A claim that a model "has an edge" must compare its pooled AUC against that `p95` for the same bars and split options — the dashboard's Pooled test AUC panel says it does not compute the null (`apps/dashboard/app/page.tsx:893-908`); `scripts/demo_ml.py` / `docs/ml-validation.json` (`null_auc_reference`) do.
5. **Fixed seeds everywhere.** `random_state=42` on `LogisticRegression`, `RandomForestClassifier` and `XGBClassifier` (`walkforward.py:79`, `94`, `102`), `"seed": 42` in the result (line 167); `SyntheticProvider(seed=42)` is the default data seed (`axiom/data/providers.py:43`); surrogates are seeded `seed + k` (`walkforward.py:197`). A new candidate must set an explicit seed or say why determinism doesn't apply.
6. **No model persistence today.** `walk_forward` fits and discards every estimator inside one call; nothing is pickled to disk. If a feature adds model persistence, that opens a new deserialization trust boundary — route it through `security` before it ships, and it needs an ADR from `architecture`.
7. **Synthetic data validates software, not skill.** Results on `SyntheticProvider`/`StableSyntheticProvider`/`benchmark_universe` data validate software behavior and cannot establish predictive value (README limitations); a claim of predictive skill needs `YahooProvider` data, the null-p95 comparison above, and the fixed-universe Yahoo study's selection/survivorship caveat.
8. **Causal features only.** `FEATURES` (`walkforward.py:21-29`) come from `axiom/features/pipeline.py`'s output and are gated on the `ready` flag (line 60); a new feature must be computable from information available at or before the bar's close and must not leak `forward_return`-adjacent information.
9. **LLM features** (none exist; none are planned): if proposed, they must never sit in the risk/execution decision path (`axiom/risk/engine.py`, `axiom/backtest/events.py`) unattended, must never treat market data, tickers or free-text fields as instructions (prompt injection), and tests must not use the network; use the official Anthropic SDK and load the `claude-api` skill for current model IDs instead of recalling them.
