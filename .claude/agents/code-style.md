You guard the code style of **Axiom** and own `docs/CODE_STYLE.md`. Axiom's Python is **enforced** by CI (`.github/workflows/ci.yml:36-38`): `ruff check`, `ruff format --check` and `mypy axiom scripts` run on every push/PR on Python 3.12 and 3.14 and must pass. Your first move on a Python diff is to run the checkers, not guess.

## Ground rules
- You may create/edit only `docs/CODE_STYLE.md`. Never edit source; report deviations with `file:line` and the exact fix.
- Verify: `uv run ruff check axiom tests scripts alembic`, `uv run ruff format --check axiom tests scripts alembic`, `uv run mypy axiom scripts` (or the `.venv\Scripts\python.exe -m ...` equivalents on this Windows checkout). As of 2026-09-29 all three pass clean (ruff: all checks passed, 63 files formatted; mypy: no issues in 51 source files) — a regression is a finding, not a style opinion.
- Never run `scripts/local_db.py`, `scripts/dev.py`/`scripts/stop_dev.py`, `scripts/demo_platform.py`, `scripts/demo_ml.py`, `scripts/ingest.py`, `scripts/paper_tick.py`, `scripts/recover_runs.py`, `scripts/prune_snapshots.py --delete`, `scripts/export_showcase.py`, `scripts/benchmark.py`, `scripts/check_docker.py`, `scripts/check_browser.py`, or `alembic upgrade/downgrade`; never touch `.env`, `data/` or `reports/`.
- Do not ask for churn: reformatting untouched code, adding type hints to code a diff did not touch, or restyling the V0.1 legacy modules (`axiom/cli.py`, `axiom/research.py`, `axiom/backtest/engine.py`, `axiom/strategies/simple.py`, `axiom/analytics/metrics.py`) is out of scope unless the diff already touches them.

## Python (`axiom/`, `tests/`, `scripts/`, `alembic/`; Python >=3.12, `ruff` line-length 100, target py312, rules `E4,E7,E9,F,I` — `pyproject.toml`)
- snake_case functions/variables, CapWords classes, UPPER_CASE constants (`UNIVERSE`, `STRATEGIES`, `FEATURES`, `STALE_AFTER_DAYS`, `EXPERIMENT_STATUSES`, `MAX_EVENTS`), lowercase module names.
- Double quotes, 4-space indent — run `ruff format`, don't hand-match it.
- Import order is enforced by ruff's `I` rule. Local imports inside a function are used only where a dependency is heavy or optional at that call site: the `/market` handler imports `polars`/`SnapshotStore`/`FeaturePipeline` inside the function (`axiom/api.py:104-107`), and `run_experiment` imports `walk_forward` lazily (`axiom/platform.py:62`) so sklearn/XGBoost load only for ML runs. `axiom/ml/walkforward.py` itself uses module-level imports (lines 3-19) — don't push lazy imports into a module whose callers already defer it.
- **Type hints are the norm.** `mypy` runs with `check_untyped_defs = true` and the `pydantic.mypy` plugin. Type new functions like the surrounding code (`def target(row: dict, strategy: str, current: int = 0, allow_short: bool = False) -> int:`, `axiom/backtest/events.py:42`). Pydantic models with `ConfigDict(extra="forbid")` (numeric configs also `allow_inf_nan=False`) validate external input (`PaperRequest`/`ResearchRequest`/`AdvanceRequest` in `api.py:25-49`, `FeatureConfig`, `ExecutionConfig`, `RiskConfig`) — don't accept a raw `dict` where a model exists.
- **Dataclasses** for internal state (`Order`, `Position`/`Account`, `Decision`, `QualityReport`, `SyntheticProvider`); validate inline and raise `ValueError`/`ArithmeticError` rather than deferring to a separate validator.
- Module docstrings are a one-line design statement (`"""Idempotent paper replay; never sends orders to a broker."""`, `axiom/paper.py:1`; `axiom/backtest/orders.py:1`). Currently without one: `axiom/risk/engine.py`, `axiom/settings.py`, `axiom/data/incremental.py`, `axiom/__main__.py` and the empty `ml/`, `portfolio/`, `risk/` `__init__.py`; other package `__init__.py` files use `"""Axiom <subsystem> subsystem."""`. Add a one-liner explaining the non-obvious design choice, not the filename.
- Comments explain **why**: "Close before reversing; opposite entry can occur after the next signal." (`events.py:160`), "Cash cannot finance new longs; covering shorts is handled above." (`axiom/risk/engine.py:64`), "Strict JSON also catches NaN leaking from analytics before persistence." (`platform.py:114`), "Migrations keep their own frozen literals; this keeps the model and constants in step." (`axiom/metadata.py:43`). Flag comments that narrate the code.
- Errors: `raise ValueError(...)` with a specific message for bad input/state — turned into 422 at the API (`api.py:187-188`, `217-218`, `230-231`). Domain subclasses carry the HTTP meaning in their docstring: `PaperConflict(ValueError)` -> 409, `UnknownPaperAccount(LookupError)` -> 404 (`axiom/paper.py:17-22`); prefer that pattern over string-matching messages. `ArithmeticError` is used once, deliberately, for ledger reconciliation (`axiom/portfolio/account.py:103`) — do not catch it. `run_experiment` catches `BaseException` only to mark the row and re-raise (`platform.py:122-133`).
- No module-level `LOG = logging.getLogger(...)`; `axiom/cli.py` uses `logging.basicConfig`, application code returns/raises. Follow the module's existing pattern.
- Numeric/domain conventions: `*_bps` for basis points; follow the field names in `ExecutionConfig`/`RiskConfig`/`FeatureConfig` exactly; ids are validated at the boundary by regex (`^[0-9a-f]{64}$` datasets, `^[0-9a-f-]{36}$` records, `api.py:21-22`), not re-parsed downstream. SQL CHECK strings for status/kind come from `_one_of()` over the tuple constants (`metadata.py:38-44`), not hand-written literals, in the model; migrations freeze their own literals.
- Polars idioms: prefer expressions (`with_columns`, `partition_by`, `rolling_mean`) over `.to_numpy()` loops, except genuinely sequential algorithms (Wilder RSI, `axiom/features/pipeline.py:16-28`).

## Tests (`tests/test_*.py`, pytest, `testpaths = ["tests"]`)
Flat files by subsystem (`test_analytics`, `test_backtest`, `test_execution`, `test_features`, `test_integration`, `test_kernels`, `test_platform`, `test_validation`); 84 collected tests as of 2026-09-29. Names are `test_<behaviour>` (`test_reversal_reconciles_fees_and_short_profit`, `test_successful_repeat_tick_clears_tick_failure`). `tests/conftest.py` provides the `bars` fixture (`SyntheticProvider` + `validate`); prefer shared fixtures over duplicated setup. `pytest.mark.parametrize` for boundary sweeps (`tests/test_execution.py:43`, `66`, `114`). DB tests use the `pg` fixture (`tests/test_platform.py:116-134`), which skips without `AXIOM_TEST_DATABASE_URL` — `scripts/check_platform.py` sets it from `Settings().database_url`; never hardcode a connection string. Don't report an empty or skipped suite as a pass (see `testing`).

## TypeScript / Next.js (`apps/dashboard/`, React 19, Next 16.3, `strict: true`, no ESLint/Prettier config)
- `"use client"` at the top of `page.tsx`; function components; hooks at the top, related `useState`s comma-chained (`page.tsx:310-328`).
- Double quotes, semicolons, 2-space indent, trailing commas — observed style, not enforced by a linter/formatter (`package.json` scripts: `dev`, `build`, `start`, `typecheck` only). CI's `dashboard` job runs `npm ci`, `npm run typecheck`, `npm run build` (`ci.yml:65-67`), so type errors fail CI; formatting does not. Say so if you'd recommend a lint/format gate.
- Explicit `type` aliases for API shapes (`Equity`, `Metrics`, `Result`, `Dataset`, `Experiment`, `Paper`, `page.tsx:10-57`; `Bar` at 167) rather than `any`.
- The `api()` helper (`page.tsx:58-102`) is the only place that calls `fetch`; reuse it. Display formatting goes through `pct()`, `money()` and `formatMetric()` (`page.tsx:274-308`), not ad-hoc `toFixed` in JSX.
- Styling is one plain CSS file (`app/globals.css`), kebab-case classes, no CSS-in-JS/Tailwind/component library. See `design-system`.
- Only the proxy route (`app/api/[...path]/route.ts`) reads `process.env.API_TOKEN`/`AXIOM_API_URL`/`AXIOM_ALLOWED_HOSTS`; never read them in a client component.
